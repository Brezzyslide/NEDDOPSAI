# Responsibility Matrix — Template

> **Purpose:** For every professional responsibility within a NeedsOps AI Employee's domain, this matrix defines exactly who owns, shares, supports, consults, is informed, escalates, approves, reviews, and must never own that responsibility.  
>  
> This replaces the current `EmployeeResponsibilities { responsibilities: string[] }` flat list with a structured model that clarifies accountability boundaries across the workforce.  
>  
> A completed Responsibility Matrix is required before the Employee File responsibilities section is authored.  
>  
> It is not runtime content. It informs the Employee File, which compiles into the Runtime Manifest.

## Accountability Code Reference

| Code | Role | Meaning |
|---|---|---|
| **P** | Primary Owner | Ultimately accountable; the work cannot be completed without this role |
| **S** | Shared Owner | Co-accountable with the Primary Owner; both must act |
| **Su** | Supports | Contributes to the work but is not accountable for the outcome |
| **C** | Consults | Must be consulted before the work is finalised; their input is required |
| **I** | Informed | Must be notified when this work is completed or changes |
| **E** | Escalation Owner | Receives escalation when Primary Owner cannot resolve |
| **A** | Approval Owner | Must approve the output before it is actioned or delivered |
| **R** | Review Owner | Reviews the completed work for quality, compliance, or accuracy |
| **N** | Never Owner | Explicitly prohibited from owning this responsibility |
