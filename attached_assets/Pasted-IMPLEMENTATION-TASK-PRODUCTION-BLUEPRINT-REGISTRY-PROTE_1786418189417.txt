## 3. Protect NeedsOps proprietary blueprint content

The full platform-owned blueprint specification is proprietary NeedsOps intellectual property.

Do not expose platform blueprint internals to ordinary tenant users or tenant managers.

Create explicit visibility levels:

### Ordinary user

May see:

* blueprint/work type display name
* work-product status
* resulting deliverable
* version label if appropriate

Must NOT see:

* internal section instructions
* evidence logic
* reasoning controls
* specialist routing logic
* quality scoring formulas
* completion gates
* prohibited assumptions
* escalation rules
* internal system prompts
* proprietary evidence-selection logic

### Organisation manager

May see:

* blueprint name
* purpose summary
* version
* status
* deliverable type
* attached organisation template
* organisation-configurable settings

Must NOT see/copy the full platform blueprint specification.

### Organisation owner/admin

May:

* configure organisation-specific business settings
* attach/substitute organisation templates
* create organisation-owned custom blueprints
* create permitted overrides

But a platform blueprint override must NOT reveal the underlying proprietary NeedsOps blueprint internals.

They may configure an override from an exposed schema/contract, not clone hidden system content.

### NeedsOps platform administrator

May see and manage the complete platform blueprint specification.

## 4. Separate public metadata from private specification

A platform blueprint should have two conceptual layers:

`BlueprintDescriptor`

Safe to expose:

* code
* title
* purpose
* category
* modes
* version
* status
* primary deliverable
* supported formats

and:

`BlueprintSpecification`

Platform-private:

* required sections
* section instructions
* evidence requirements
* validation rules
* claim-integrity rules
* quality rules
* prohibited assumptions
* specialist routing
* completion gates
* escalation
* internal execution instructions

APIs must not accidentally return the private specification to tenant roles.

Add tests for this.

## 5. Preserve organisation custom blueprint capability

Organisation-owned blueprints remain organisation property and should be fully visible/editable to authorised organisation admins.

Distinguish:

`platform_owned`
vs
`organisation_owned`

Platform blueprint internals remain protected.

Organisation admins can fully inspect blueprints their organisation created itself.

## 6. Template architecture

Templates remain separate from blueprints.

Organisation administrators should be able to see/manage templates their organisation owns.

The association should support:

platform blueprint
+
platform default template

OR:

platform blueprint
+
organisation template substitution.

The organisation should not need to see the platform blueprint internals merely to substitute a template.
