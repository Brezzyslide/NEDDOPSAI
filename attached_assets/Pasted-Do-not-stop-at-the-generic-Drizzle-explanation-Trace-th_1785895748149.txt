My strongest suspicion

Given the recent amount of schema and service work, I would check for a stale @workspace/db build first.

A common monorepo failure looks like this:

Schema source:
workPackageManifests.someNewColumn ✅

API runtime’s compiled DB package:
workPackageManifests.someNewColumn === undefined ❌

The code type-checks against one representation, but the running API imports an older generated package. Drizzle then receives:

.select({
  someNewColumn: undefined
})

and crashes during _prepare().

The correct remedy in that case is:

Update/export schema
→ rebuild lib/db
→ rebuild dependent packages
→ restart API server
→ rerun delegation

Do not let Replit claim the issue is fixed until it names the exact field. “A schema column was undefined” is still only the category of failure, not the root cause.
