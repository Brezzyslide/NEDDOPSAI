Original Product Intention

NeedsOps AI+ is intended to become a multi-tenant AI operations platform where organisations subscribe to a governed AI workforce.

The platform is not intended to be merely:

* a CRM
* a static workforce directory
* a chatbot
* a compliance application
* a plan-management system
* an admin dashboard
* an API connector catalogue
* an OpenClaw control panel

The intended customer experience is:

Customer signs up
↓
Creates or joins an organisation
↓
Selects a plan or begins a trial
↓
Receives access to an AI Workforce
↓
Uses a messaging interface to give work instructions
↓
Chief of Staff identifies the correct Workforce Role
↓
Workforce Role applies its business expertise
↓
Worker Profile defines allowed tools and execution surfaces
↓
NeedsOps checks permissions, entitlements, usage and approvals
↓
OpenClaw or another runtime executes the authorised work
↓
Execution occurs through one or more of:
   - the customer’s logged-in browser
   - a secure browser extension
   - NeedsOps Connect on the customer’s local computer
   - approved local folders and applications
   - native APIs where available
↓
The customer sees progress, approves sensitive actions and receives the result
↓
All actions are tenant-isolated and audited

The intended platform-owner experience is:

NeedsOps Platform Console
↓
View and manage all organisations
↓
Manage plans, pricing and plan versions
↓
Manage workforce packs and access levels
↓
Manage trials, usage limits, overrides and support
↓
Monitor future runtimes, browser sessions, local devices and failures
↓
Operate the SaaS without changing code for ordinary commercial changes

The intended architectural chain is:

Chief of Staff
↓
Workforce Role
↓
Business knowledge and Intelligence Engines
↓
Worker Profile
↓
Execution Plan
↓
Policy and approval gates
↓
Execution Runtime
↓
Browser, local computer, files or API

Important distinctions:

* Workforce Roles define responsibility and expertise.
* Worker Profiles define permitted tools and execution surfaces.
* Intelligence Engines provide deterministic rules such as SCHADS, NDIS pricing, compliance, risk and quality.
* OpenClaw is an execution runtime, not the owner of tenancy, billing, permissions or business policy.
* APIs are preferred where reliable, but they are not required for every customer system.
* NeedsOps must work with customer systems such as ShiftCare, Lumary, Brevity, custom CRMs, MYOB, Xero and government portals through approved browser or local execution where APIs are unavailable.
* NeedsCare AI+, Need2Comply AI+ and Needs2Learn AI+ are optional external or first-party systems. NeedsOps must not depend on a customer purchasing them.

Audit Method

Inspect each sprint and each major subsystem.

For every feature, classify it as one of:

LIVE
Implemented and working end to end.
PARTIAL
Some real functionality exists, but important parts are missing.
SIMULATED
The flow works only through mock or deterministic simulation.
METADATA ONLY
Definitions, registry entries or database records exist, but no behaviour executes.
PLACEHOLDER
The page, route or interface exists primarily to reserve structure.
NOT BUILT
No meaningful implementation exists.
BROKEN
Implementation exists but currently fails.

Every major claim must include evidence such as:

* relevant package or file path
* database table
* API route
* page route
* test file
* runtime behaviour
* application output

Do not list internal IDs or secrets.
