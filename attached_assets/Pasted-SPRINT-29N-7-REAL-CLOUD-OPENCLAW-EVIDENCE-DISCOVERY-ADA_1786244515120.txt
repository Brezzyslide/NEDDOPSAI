SPRINT 29N.7 — REAL CLOUD OPENCLAW EVIDENCE DISCOVERY ADAPTER

IMPLEMENTATION + LIVE RUNTIME PROOF.

Sprint 29N.6 established:

KRS → Evidence Sufficiency → IEvidenceDiscoveryAdapter → CandidateEvidence → NeedsOps Authority Gate → EvidencePack V2 → OpenAI

The current production adapter is NullDiscoveryAdapter.

This sprint has one purpose: replace the no-op adapter with a real Cloud OpenClaw discovery adapter where OpenClaw runtime capability is genuinely available.

Do NOT redesign KRS, UEE, CandidateEvidence, Authority Registry or the acceptance gate.

A — Prove the actual Cloud OpenClaw connection first

Identify the real hosted OpenClaw runtime available to the API server.

Prove with an actual runtime call:

* runtime endpoint/broker;
* authentication;
* tenant/execution correlation;
* tool/skill availability;
* structured response support;
* ability to search/read permitted resources;
* ability to access external web sources if supported.

Do not implement a fake adapter around mocks.

If there is no real Cloud OpenClaw runtime, STOP and report that.

B — Reuse existing infrastructure

Investigate whether:

/v1/execution → ExecutionPackage → OpenClawExecutionEngine → RuntimeBrokerClient

should provide the transport.

Do not create a third OpenClaw transport stack if the existing broker infrastructure is suitable.

The evidence-discovery adapter should be a bounded capability over the existing transport wherever technically sound.

C — Implement CloudOpenClawEvidenceDiscoveryAdapter

It must implement the existing IEvidenceDiscoveryAdapter.

Input must contain only the governed discovery scope generated by NeedsOps:

* organizationId
* executionId
* specialistCode
* unresolved references / required evidence
* allowed source classes
* maximum hops
* maximum sources
* maximum passages
* timeout
* allowed domains/providers where applicable

It must NOT receive unrestricted organisational access.

Output:

CandidateEvidence[]

using the existing 29N.6 contract.

D — OpenClaw’s job is discovery only

Explicit OpenClaw instruction:

Locate and return evidence. Do not perform the final professional analysis.

OpenClaw may:

* search
* locate
* read
* traverse references
* retrieve passages
* identify source metadata

OpenClaw must not:

* determine organisational authority
* make final compliance conclusions
* write final recommendations
* create Completed Work
* mark claims grounded
* approve anything

E — Internal multi-hop live proof

Use a controlled document chain:

Complaints Policy
→ Escalation Procedure
→ Incident Management Policy

KRS must run first.

Expected:

1. KRS EvidencePack V1 produced.
2. Sufficiency returns UNRESOLVED_REFERENCE.
3. Real OpenClaw adapter invoked.
4. OpenClaw follows the reference within the configured hop limits.
5. CandidateEvidence returned.
6. NeedsOps Authority Gate validates it.
7. Accepted evidence enters EvidencePack V2.
8. Sufficiency reruns.
9. OpenAI, not OpenClaw, performs the final analysis.

Capture the entire trace.

F — External authority live proof

Use a controlled request requiring an official external source.

Expected:

1. KRS finds internal policy.
2. Sufficiency = EXTERNAL_AUTHORITY_REQUIRED.
3. OpenClaw searches for official external authority.
4. OpenClaw returns URL, publisher, passage and metadata.
5. Authority Registry verifies the source.
6. Candidate becomes AcceptedEvidence.
7. EvidencePack V2 contains internal + external evidence.
8. OpenAI performs the comparison.

Unknown blogs/secondary sites must not become authoritative evidence.

G — Failure proofs

Prove:

* OpenClaw unavailable → KRS-sufficient task still succeeds.
* OpenClaw unavailable + escalation required → fail honestly before Completed Work.
* wrong tenant candidate → rejected.
* fabricated source → rejected.
* superseded source → rejected.
* unknown external domain → rejected/governance required.
* timeout → no unsupported work generated.
* duplicate callback/result → no duplicate evidence.

* OpenClaw dispatch
* OpenClaw investigation
* Authority Gate
* EvidencePack V2
* second sufficiency evaluation
* OpenAI generation
* total runtime

Report how much escalation adds over KRS-only execution.
