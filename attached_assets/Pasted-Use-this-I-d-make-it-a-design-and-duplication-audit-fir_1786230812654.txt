SPRINT 29N — NEEDSOPS VS OPENCLAW RESPONSIBILITY & DUPLICATION AUDIT

INVESTIGATION / ARCHITECTURE DESIGN ONLY.

DO NOT IMPLEMENT, DELETE, REFACTOR OR MIGRATE ANYTHING.

The purpose of this sprint is to answer one strategic architecture question:

Which capabilities should NeedsOps own itself, and which capabilities should be delegated to OpenClaw skills/plugins/runtime instead of being reimplemented inside NeedsOps?

The desired conceptual split to test is:

NeedsOps = control plane

* understand the user request
* classify work
* select/authorise worker
* govern permissions and approvals
* enforce evidence and authority rules
* manage Tasks / Active Work / Completed Work
* preserve versions, provenance and audit
* maintain organisational context/memory
* present the product UX

OpenClaw = execution plane

* locate/read/write files
* use local/remote tools
* browser interaction
* Word/Excel/document operations
* connector actions
* desktop/local execution
* operational task execution
* specialist skills/plugins

DNA = worker behaviour/configuration

* role
* operating style
* responsibilities
* allowed tools
* decision boundaries
* escalation behaviour

Core hypothesis:

OpenClaw does. NeedsOps decides, governs, remembers and records.

Do not assume this is correct. Prove or challenge it against the actual codebase and current OpenClaw integration.

The answer I’d be looking for is not “replace everything with OpenClaw.” The useful result is a clean boundary. If the audit proves OpenClaw can reliably own the doing, then we can stop growing NeedsOps sideways and concentrate our engineering on the parts that actually make NeedsOps different: control, governance, organisational intelligence, trust and finished work.
