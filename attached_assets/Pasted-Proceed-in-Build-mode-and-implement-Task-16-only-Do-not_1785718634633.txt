2. INGESTION ARCHITECTURE
────────────────────────────────────────

Implement an asynchronous ingestion pipeline:

Upload completed
→ validate source and current version
→ create ingestion job
→ fetch object privately
→ extract text
→ normalise content
→ detect headings and sections
→ chunk content
→ calculate lexical index
→ generate embeddings
→ store chunks
→ mark source as review_required
→ authorised user reviews and approves
→ only then may the source become retrievable in Task #17

Required properties:

- idempotent
- retryable
- cancellable
- resumable where practical
- auditable
- tenant-isolated
- version-aware
- no duplicate processing for the same checksum and version
- safe failure state
- no silent success
- no retrieval before approval

Create an ingestion service and job abstraction rather than running all work inside a request handler.

────────────────────────────────────────
3. SUPPORTED FILE TYPES
────────────────────────────────────────

Initial supported formats:

- PDF
- DOCX
- TXT
- Markdown

Do not implement XLSX yet unless there is already reliable extraction support in the repository.

Requirements:

PDF:
- extract page-level text where possible
- retain page numbers
- detect empty or scanned PDFs
- do not claim OCR was performed unless an OCR adapter actually ran

DOCX:
- preserve headings and paragraphs where possible
- identify tables and numbered procedures where possible

TXT and Markdown:
- preserve headings and paragraph structure
- normalise line endings
- preserve list structure where practical

Reject:

- encrypted files that cannot be opened
- unsupported formats
- corrupted files
- executable content
- unexpectedly huge extracted text
- suspicious archive payloads

5. NORMALISATION
────────────────────────────────────────

Implement deterministic normalisation:

- Unicode normalisation
- line-ending normalisation
- excessive whitespace removal
- repeated page-header/footer reduction where practical
- preservation of headings
- preservation of numbered procedures
- preservation of bullet lists
- preservation of section boundaries
- safe removal of binary artefacts
- stable text hashing

Do not rewrite the meaning of policies or care documents.

Do not use an LLM to silently “improve” source text.

6. CHUNKING STRATEGY
────────────────────────────────────────

Implement heading-aware, paragraph-aware chunking.

Requirements:

- prefer complete sections
- retain heading path
- retain page number where available
- use modest overlap
- respect token limits
- avoid splitting numbered procedures where practical
- avoid splitting tables carelessly
- stable chunk ordering
- stable content hashes
- configurable chunk size and overlap
- support re-chunking when strategy version changes

Record:

- chunkIndex
- sectionTitle
- headingPath
- pageNumber
- text
- tokenCount
- contentHash
- chunkingStrategy
- chunkingStrategyVersion

Add missing schema fields through a migration if necessary.

────────────────────────────────────────
9. SENSITIVE DOCUMENT HANDLING
────────────────────────────────────────

Add stronger controls for high-sensitivity content such as:

- care plans
- Behaviour Support Plans
- participant files
- clinical records
- incident details
- HR files
- legal documents

Requirements:

- sensitivity classification carried into every chunk
- no embedding generation if the organisation has disabled external embedding for that sensitivity level
- provider policy checks before sending text externally
- future support for private/self-hosted embeddings
- audit event for every embedding batch
- no raw document text in ordinary logs
- no participant names or identifiers in diagnostic logs
- configurable retention
- source revocation deletes or disables derived chunks and embeddings

Do not assume every source may be sent to a third-party model provider.

10. PROMPT-INJECTION AND DOCUMENT-POISONING PRECHECK
────────────────────────────────────────

Task #17 will enforce runtime protections, but Task #16 must add ingestion-time analysis hooks.

Detect and flag likely instruction-like content such as:

- “ignore previous instructions”
- “system prompt”
- “send data to”
- “reveal secrets”
- hidden or suspicious embedded text
- unusual repeated prompt patterns

Requirements:

- flag, do not silently rewrite
- store warning metadata
- require human review for high-risk flags
- do not automatically approve flagged sources
- keep the source available for authorised inspection
- no claim that detection is perfect
