# NeedsOps AI+

## Sprint 1 Email Delivery Completion Fix

The invitation workflow is creating invitation records and secure invitation links successfully, but invitation emails are currently only printed to the server console.

Complete the Sprint 1 invitation workflow by implementing real transactional email delivery through Resend.

Do not begin Sprint 2.

## Required architecture

Create a provider-independent email abstraction inside the existing application architecture.

Suggested interface:

```typescript
interface TransactionalEmailService {
  sendInvitationEmail(input: InvitationEmailInput): Promise<EmailDeliveryResult>;
  sendVerificationSupportEmail?(input: VerificationEmailInput): Promise<EmailDeliveryResult>;
  sendPasswordResetSupportEmail?(input: PasswordResetEmailInput): Promise<EmailDeliveryResult>;
}
```

Create:

* `ResendEmailService`
* `DevelopmentEmailService`
* shared email templates
* email delivery result types
* structured delivery logging

The invitation service must depend on the interface, not directly on the Resend SDK.

## Environment variables

Add these variables to `.env.example`:

```env
RESEND_API_KEY=
EMAIL_FROM_ADDRESS=
EMAIL_FROM_NAME=NeedsOps AI+
WEB_APP_URL=
EMAIL_DELIVERY_MODE=development
```

Supported delivery modes:

```text
development
resend
```

In development mode:

* do not claim an email was delivered
* log the invitation URL safely
* return a delivery status of `development_preview`
* never log the raw invitation token separately from the complete preview URL

In Resend mode:

* require `RESEND_API_KEY`
* require a valid sender address
* send the actual email
* record the Resend message ID where returned
* handle provider errors safely

## Invitation creation behaviour

When an invitation is created:

1. validate permission
2. validate email and role
3. validate seat availability structurally
4. create secure plaintext token
5. store token hash
6. create invitation record
7. build the acceptance URL
8. send the invitation email through `TransactionalEmailService`
9. update delivery state
10. record audit events
11. return a safe response

If email delivery fails:

* do not delete the valid invitation
* return that the invitation was created but email delivery failed
* allow an authorised user to resend it
* show the failure state in the Team page
* log the failure without exposing secrets

Suggested response:

```json
{
  "success": true,
  "data": {
    "invitationCreated": true,
    "emailDelivery": "failed",
    "message": "The invitation was created, but the email could not be delivered."
  }
}
```
