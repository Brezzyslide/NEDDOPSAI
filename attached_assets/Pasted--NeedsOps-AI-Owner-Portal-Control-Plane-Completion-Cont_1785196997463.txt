# NeedsOps AI+

## Owner Portal Control Plane Completion

Continue from the current Platform Console, Pack Builder, commercial services, organisation administration, trials, workforce packs, capability system and specialist runtime.

The objective of this sprint is to turn the current Owner Portal from a mostly read-only monitoring dashboard into the complete operating control plane for the NeedsOps business.

After this sprint, an authorised platform owner must be able to manage organisations, plans, pricing, packs, trials, platform staff, commercial access, onboarding selections, execution access and support actions without manually editing the database or calling APIs outside the UI.

Do not begin Stripe, AWS OpenClaw deployment, local-device access or unrelated connector work.

---

# Core Principle

The Owner Portal must become the authoritative control surface for ordinary platform operations.

The platform owner should not need a developer to:

* grant a pack
* revoke a pack
* start or extend a trial
* convert a trial
* create a plan
* publish pricing
* suspend an organisation
* change seats
* approve an access request
* grant a platform role
* freeze execution
* activate individual specialists
* correct onboarding pack selection

All actions must use existing service and API layers where possible.

Do not implement direct database mutations from React components.

---

# Required Owner Experience

The intended flow is:

```text
Platform owner signs in
↓
Opens Owner Portal
↓
Views organisations, subscriptions, trials and usage
↓
Changes commercial or operational settings
↓
NeedsOps validates permissions and state
↓
Change is persisted
↓
Tenant entitlements and capabilities recalculate
↓
Customer UI reflects the change
↓
Audit event records the action
```

```text

```

9. return the result to onboarding UI
