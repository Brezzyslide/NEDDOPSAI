Sprint 9.5 — Specialist Eligibility and Specialist Runtime

Continue from the completed capability identification and entitlement sprint.

The purpose of this sprint is to close the gap between:

Capability approved
↓
Specialist assigned

and:

Capability approved
↓
Eligible specialist selected
↓
Temporary specialist run created
↓
Specialist performs domain reasoning
↓
Structured result returned
↓
Chief of Staff consolidates
↓
OpenClaw-ready execution package created

Do not begin AWS deployment, browser automation, local-device access, Stripe or unrelated connector work.

⸻

Core Objectives

This sprint must deliver:

1. Specialist eligibility enforcement inside task planning
2. Temporary specialist runs
3. Specialist work packages
4. Real specialist reasoning through the AI Privacy Gateway
5. Role-specific specialist instructions
6. Structured specialist outputs
7. Specialist retries, clarification and failure handling
8. Parallel and dependent specialist execution
9. Chief of Staff consolidation
10. OpenClaw-ready execution packages
11. Task Workroom specialist progress
12. Platform Console specialist monitoring

The current Workforce Roles must no longer be treated only as labels attached to a task.

⸻

Non-Negotiable Architecture

Preserve this chain:

Customer request
↓

↓

↓

↓

↓

↓

12. Clarification Workflow

When a specialist is blocked:

1. move the run to awaiting_clarification
2. create a structured clarification card in the Task Workroom
3. explain why the answer is required
4. identify the requesting specialist
5. block only dependent runs
6. allow unrelated runs to continue
7. validate the user response
8. update specialist context
9. requeue the run
10. resume dependent steps when ready

Do not restart the entire task.
