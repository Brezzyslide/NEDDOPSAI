# NeedsOps AI+

## Sprint 9.6 — Dynamic Workforce Pack Pricing and Automatic Onboarding Assignment

Continue from the current Pack Builder, public pack catalogue, onboarding pack picker and customer Plan page marketplace.

The objective of this sprint is to remove seeded commercial prices, make Workforce Pack pricing fully owner-controlled through the Platform Console, ensure those prices display consistently across the landing page, onboarding and customer Plan page, and automatically assign selected packs during organisation creation.

Do not begin Stripe, OpenClaw deployment, local-device access or unrelated connector work.

---

# Core Commercial Principle

Workforce Pack pricing must be controlled from the NeedsOps Platform Console.

Do not hard-code or seed live commercial prices such as:

```text
A$299 per month
A$399 per month
```

The database may contain pack definitions, but commercial pricing must be created and maintained by an authorised platform owner.

If a public pack has no active price configured, the public UI must display:

```text
Contact NeedsOps
```

or:

```text
Pricing coming soon
```

depending on the pack configuration.

Do not display zero as a substitute for missing pricing unless the pack is explicitly marked as free.

---

# Required Customer Flow

Implement this end-to-end flow:

```text
Platform owner creates or edits Workforce Pack
↓
Platform owner sets active monthly and annual price
↓
Platform owner publishes the pack
↓
Landing page reads published pack and active price from DB
↓
Customer selects pack during onboarding
↓
Organisation is created
↓
Core Pack is granted automatically
↓
Selected packs are granted according to onboarding commercial rules
↓
Tenant pack entitlements are created
↓
Pack capabilities become available
↓
Customer sees granted packs on the Plan page
```

The customer must not select a pack during onboarding and then find that it was ignored.

# 1. Remove Seeded Commercial Prices

Update seeds so they do not define active live pricing for paid Workforce Packs.

Seed only stable pack metadata where needed:

* pack code
* pack name
* description
* icon
* colour
* tagline
* display order
* status
* specialist mappings
* capability mappings

Do not seed:

* monthly price
* annual price
* promotional price
* trial price
* sale price

unless the pack is explicitly free.

The Core Pack may be seeded as:

```text
is_free = true
monthly_price_cents = 0
annual_price_cents = 0
```

All paid packs should begin with:

```text
pricing_status = not_configured
```

or the equivalent existing status.

Do not overwrite prices already configured by the platform owner when seeds run again.

All seeds must remain idempotent.

# 3. Owner-Controlled Pack Pricing

Update `/platform/packs`.

The platform owner must be able to:

* create a pack
* edit pack metadata
* set pack as free or paid
* create a draft price version
* set monthly price
* set annual price
* set currency
* set effective date
* schedule future pricing
* publish pricing
* supersede old pricing
* archive pricing
* remove public price visibility
* set fallback display text
* preview the public customer display

Do not allow active prices to be overwritten directly.

Editing an active price must create a new version.

Example:

```text
Compliance Workforce
Price version 1
A$249 monthly
A$2,490 annually

Price version 2
A$299 monthly
A$2,990 annually
Effective from 1 January 2027
```

Existing customers should remain on their assigned commercial terms unless explicitly migrated.

New customers should receive the active current price.

# 4. Currency Handling

Default currency should be:

```text
AUD
```

Display as:

```text
A$299/month
A$2,990/year
```

Do not display an ambiguous `$299`.

Support future currencies, but do not convert currencies automatically.

Every price must carry an explicit ISO currency code.

The public endpoint must return only:

* published packs
* publicly visible packs
* available packs
* packs with current public metadata
* active price version where available

  code: string;
  name: string;
  icon: string;
  colour: string;
  tagline: string;
  description: string;
  specialistCount: number;

Do not return internal pricing notes or unpublished price versions.

# 11. Trial Behaviour

The platform owner must control trial rules.

Per pack configure:

* trial available
* trial length
* auto-grant on signup
* capabilities available during trial
* execution access during trial
* connector access during trial
* whether payment is required after trial
* whether manual approval is required

Do not assume every pack has the same trial length.

When the trial expires:

* professional analysis access should follow configured rules
* execution access should stop unless activated
* customer data and history must remain accessible according to retention policy
* the customer should see upgrade guidance
* no specialist run should continue after entitlement expiry unless already authorised by policy

# 16. Pricing Validation

Implement server-side validation.

Rules:

* monthly price cannot be negative
* annual price cannot be negative
* free packs must have zero pricing
* paid packs cannot be marked free
* active price requires currency
* active price requires effective date
* only one active current public price per pack and currency
* scheduled price cannot overlap another scheduled or active price
* archived pack cannot publish new pricing
* public pack with no active price must have a fallback display mode

---

# 17. Caching

The landing page and pack marketplace should not require expensive pricing queries on every render.

Introduce a safe cache behind an interface.

The database remains authoritative.

Invalidate cache when:

* pack published
* pack unpublished
* price activated
* price superseded
* visibility changed
* trial configuration changed

Do not store pricing only in process memory.
