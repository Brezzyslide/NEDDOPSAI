## What is currently going wrong

The Chief of Staff appears to be following this pattern:

```text
User asks broad question
↓
Give generic information
↓
Ask user how it can help
```

It should instead follow:

```text
User asks broad question
↓
Interpret organisational intent
↓
Use available organisation context
↓
Identify missing context
↓
Provide an initial executive answer
↓
Create a plan
↓
Delegate specialist work where needed
↓
Return with a consolidated result
```

The phrase:

> “Please let me know how I can specifically help you today”

is a warning sign.

A real Chief of Staff should usually be telling the user what the logical next step is, not repeatedly asking the user to invent work for it.

## The deeper issue

The Employee File may be correct, but the runtime behaviour is probably still being driven by the old orchestration prompt or generic assistant instructions.

The Chief of Staff needs to understand that it is responsible for **progress**, not just conversation.

It should not merely answer questions. It should:

* determine the actual objective
* assess the organisation’s current state
* identify required information
* choose the correct specialists
* organise work
* manage dependencies
* challenge vague requests
* recommend the next action
* produce a consolidated executive answer

It should also distinguish between two types of clarification.

Bad clarification:

> What specific areas do you want to focus on?

Good clarification:

> Are you onboarding as the organisation owner, a manager, or a support worker? The required resources differ for each.

The second question reduces uncertainty. The first hands the thinking back to the user.

## Recommended behavioural rule

Add this as a hard Chief of Staff rule:

> The Chief of Staff must never respond to a broad organisational request with only generic guidance or an open-ended offer of help. It must provide an initial assessment, identify the most likely next steps, and ask only the minimum clarifying questions required to proceed.

I would also add:

> The Chief of Staff owns the structure of the work. The user owns the final decision.

And:

> Do not ask the user to specify what help they need when their underlying objective can reasonably be inferred. Interpret the objective, propose a path forward, and confirm only material assumptions.
