Part B — Production redundancy and dead-code audit

Now inspect the actual runtime architecture and identify code that is still part of the repository or production build but is no longer necessary for the functionality NeedsOps currently provides.

Trace from live routes and UI entry points inward, rather than simply searching for files that look old.

For every candidate identify:

* what it was originally intended to do
* whether anything currently imports or calls it
* whether it participates in Cloud, Hybrid/Desktop, or both
* whether another production component now performs the same responsibility
* whether removing it affects tests, migrations, stored historical records or API compatibility
* whether it is dead, deprecated, redundant, transitional, or genuinely still required

Pay particular attention to architecture accumulated during the previous execution-engine iterations, including:

* legacy execution paths
* endToEndWorkflowService

* unused action/tool proposal infrastructure

* obsolete approval paths
* superseded conversation dispatch logic
* unused feature/entitlement checks
* duplicate adapters
* abandoned schema/service abstractions
* frontend pages/components no longer reachable
* old APIs with no callers

Do not assume /v1/execution or OpenClaw-related infrastructure is redundant merely because the current Cloud UEE does not use it. Tomorrow we intend to connect a real NeedsOps OpenClaw instance running on a MacBook and test it as a remote execution/discovery runtime. Preserve anything that could reasonably form part of that Cloud/Hybrid boundary until its role is understood.

Part C — Classify before deleting

Put every candidate into one of four buckets:

KEEP — required by current production architecture.

KEEP FOR OPENCLAW — not currently exercised by primary Cloud UEE but likely required for tomorrow’s OpenClaw Cloud/Hybrid integration.

DEPRECATE — still has compatibility/history value but should no longer receive development.

DELETE — proven unreachable/redundant and safe to remove.

Nothing is deleted merely because it has no current frontend caller. Check backend callers, scheduled/background execution, connector usage, tests and cross-package imports.

Part D — Remove only proven dead code

Once classified, remove DELETE items only.

Clean imports, exports, routes, tests and dependencies associated solely with deleted architecture.

Do not drop historical database tables or migrations during this sprint unless there is overwhelming proof that doing so is necessary. Prefer leaving historical schema alone while removing unused application code.

After cleanup rerun the complete deterministic suite.
