SPRINT 29N.3 — OPENCLAW AS COMMON CLOUD + HYBRID CAPABILITY RUNTIME — ARCHITECTURE PROOF GATE

INVESTIGATION AND DESIGN ONLY. NO IMPLEMENTATION.

Do not remove, refactor, migrate, or plug OpenClaw into the Cloud runtime yet.

We now have three established facts:

1. NeedsOps Cloud can currently perform professional knowledge work end-to-end without OpenClaw:
    * Organisation Library ingestion
    * KRS retrieval
    * OpenAI reasoning
    * specialist DNA
    * self-review
    * claim/evidence validation
    * Completed Work
    * approval
    * PDF/DOCX
2. OpenClaw is partially present in the API server through a separate /v1/execution path, but the primary UEE Cloud professional-work path does not call it.
3. We want to determine whether OpenClaw should become a common capability/runtime layer that can operate in both:
    Cloud — hosted tool/resource execution
    Hybrid — customer/local/private-environment execution

while preserving a single NeedsOps intelligence/governance architecture.

The target hypothesis to investigate is:

NeedsOps decides, governs, supplies DNA/context/evidence, remembers and records.

OpenAI performs professional reasoning where appropriate.

OpenClaw provides controlled reach, resource access and operational capabilities.

But do NOT assume this split is automatically correct. Prove the best boundary.

PART D — KRS AND OPENCLAW BOUNDARY

This is one of the most important questions.

We do NOT want OpenClaw to simply search every file it can see and decide which one is organisational truth.

Investigate these models.

Model 1 — KRS-first

NeedsOps:

* determines eligible sources
* filters tenant
* filters approved/current/effective
* applies sensitivity and authority rules
* retrieves/ranks evidence

Then passes authorised passages/resources to OpenClaw.

Model 2 — OpenClaw discovery, KRS governance

OpenClaw may discover candidate files/resources.

Candidates are returned to NeedsOps.

NeedsOps ingests/resolves them through the Library/KRS authority model before professional claims can rely on them.

Model 3 — OpenClaw direct retrieval

OpenClaw searches and reads directly during specialist execution.

Determine whether this model can preserve:

* tenant isolation
* approved/current source rules
* authority scoring
* version integrity
* evidence snapshots
* claim provenance
* absence verification

If it cannot, reject it.

Recommend the clean boundary.
