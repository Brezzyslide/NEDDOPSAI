SPRINT 29K.2 — DURABLE EVIDENCE FOUNDATION

IMPLEMENTATION SPRINT

Implement Phase 1 of the claim-level evidence architecture only.

Do NOT implement:

- claim emission
- claim taxonomy UI
- recommendation linkage
- absence findings
- external trusted sources
- passage-level Evidence tab UI

This sprint establishes durable execution-time evidence provenance.

==================================================
CORE OBJECTIVE
==================================================

The EvidencePack used to generate a Completed Work version must no longer disappear after execution.

Persist enough execution-time evidence to answer later:

- Which sources were available?
- Which exact chunks were used?
- Which source version did they come from?
- What section/page did the specialist see?
- What was the relevance score?
- Has the underlying chunk changed or been re-ingested since?
- What excerpt can safely be shown even if the live chunk is no longer available?

Do not persist the entire EvidencePack JSON blob.

Use the verified HYBRID model.

==================================================
B — PASSAGE SNAPSHOT RULE
==================================================

Do not hard-code the architecture around:

"first 500 characters of chunk"

Preferred rule:

If retrieval exposes a matched span / highlighted region:
    snapshot the supporting passage around that span

Else:
    snapshot a deterministic excerpt of the chunk

Maximum snapshot size should be bounded.

Recommended:
500–1000 characters.

The passageHash MUST be computed from the FULL chunk text at execution time.

Use SHA-256.

This means:

snapshot = display/audit excerpt
hash = integrity of full passage/chunk

==================================================
C — VERSION OWNERSHIP
==================================================

Evidence provenance belongs to the exact Completed Work VERSION generated from that evidence.

Do not wait until approval to assign evidence to a version.

Flow:

EvidencePack
→ specialist generation
→ Completed Work version created
→ evidence snapshot persisted against that versionId

If later:

V1 → V2

each version must retain its own provenance.

Approval later pins one version using approvedVersionId.

Evidence for V1 and V2 must remain distinct.

==================================================
D — PERSISTENCE TIMING
==================================================

Persist evidence only after:

- generation succeeds
- Completed Work version exists

Do not persist speculative evidence for a generation that never produces a Completed Work version unless current audit architecture explicitly requires it.

Recommended flow:

resolve EvidencePack
→ generate
→ self-review
→ create Completed Work/version
→ persist evidence snapshot + links
→ continue lifecycle

If evidence persistence fails:

DO NOT silently swallow the error.

Classify the failure.

Because this is audit/provenance data, decide whether execution should:

A. fail the Completed Work creation
or
B. preserve Completed Work but mark provenance persistence failure

Use existing architecture consistency.

Do not invent behaviour without inspection.

At minimum:
structured logging + inspector diagnostic.

==================================================
E — IDEMPOTENCY
==================================================

Evidence persistence must be idempotent.

Re-running callback/recovery logic for the same:

executionId + versionId

must not duplicate:

snapshot rows
evidence link rows

Use unique constraints/upsert-safe logic.

==================================================
H — SOURCE RE-INGESTION INTEGRITY
==================================================

Add a deterministic verification helper:

verifyEvidencePassageIntegrity(evidenceLink)

Behaviour:

1. Try to load live chunk by chunkId including soft-deleted rows where permitted.
2. If found:
   compute SHA-256(live chunk text)
   compare to passageHash

Results:

MATCH
→ integrityStatus = "verified"

NOT FOUND
→ integrityStatus = "snapshot_only"

HASH MISMATCH
→ integrityStatus = "changed"

Do not mutate historical evidence.

Do not replace the snapshot with current chunk text.
