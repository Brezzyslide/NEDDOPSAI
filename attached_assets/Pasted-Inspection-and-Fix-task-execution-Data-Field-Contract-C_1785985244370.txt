Inspection and Fix — task_execution Data Field Contract

Current error:

Specialist execution failed:

Data fields not permitted for purpose "task_execution":

- organisation_library_sources
- cos_memories
- entity_knowledge
- task_uploads

Permitted fields:

- task.id
- task.title
- task.description
- task.executionPlan
- specialist.name
- specialist.capabilities

The execution role and purpose are now correct. The remaining failure is that the task_execution data-field allowlist still reflects the old metadata-only execution architecture.

Do not disable field validation.
Do not add wildcard access.
Do not allow every runtime field.
Do not bypass clearance, tenant isolation, or source approval rules.

Objective

Align the task_execution permission contract with the current evidence-aware specialist runtime while preserving least-privilege access.

Part 5 — Purpose-specific access

Review the permitted fields for all AI purposes:

- conversation
- task_execution
- specialist_reasoning
- self_review
- knowledge_retrieval
- completed_work_generation
- clarification
- any other registered purposes

Ensure task_execution has only the context required to perform professional work.

Do not accidentally grant the same fields to every purpose.

For example:

conversation may receive library presence metadata but not evidence chunks.

task_execution may receive retrieved evidence chunks.

self_review may receive the draft and evidence citations but not unrelated memory.

Document the separation.

Part 6 — Clearance and source safety

Before any field is sent under task_execution, verify:

Organisation library evidence:

- correct organisation
- approved
- current
- indexed
- relevant to task
- specialist clearance permits access

Organisation memory:

- approved where required
- not retired
- relevant
- specialist scope permits access

Entity knowledge:

- correct entity
- correct organisation
- clearance-compatible
- task-relevant

Task uploads:

- belong to this task
- belong to this organisation
- safe/validated
- user-authorised
- only required content included

Field permission is not a substitute for row-level or clearance validation.
